# Code Review

当用户要求「审查代码 / 帮我 review 改动」时，执行本技能：

1. 用 `list_files` 与 `search_files` 定位工作目录中的源码与最近改动
   （可用 `execute_command` 执行 `git status` 或 `git diff` 了解改动范围）；
2. 用 `read_file` 逐文件通读相关代码，理解改动意图；
3. 按以下维度分析，每条意见标注 **严重/一般/建议** 级别：
   - **正确性**：逻辑错误、边界条件、空值/越界、潜在的 bug；
   - **安全性**：路径越界、命令注入、密钥或敏感信息泄露；
   - **可维护性**：命名语义、重复代码、无效注释、过度设计；
   - **测试**：改动是否缺少对应测试、是否覆盖关键路径；
4. 输出格式：
   - 先给一行总体结论（代码质量如何、是否可合并）；
   - 再按严重级别从高到低列出意见，注明 `文件:行号`；
   - 结尾指出最需要修改的一到两处，作为下一步行动。
